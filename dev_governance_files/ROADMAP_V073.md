## Product positioning

v0.7.3 adopts a **Codex-led acquisition, provider-truthful product** position.
The preferred public shorthand is:

> **Codex and more**

This phrase is allowed in high-level discovery surfaces because Codex is the
primary user-acquisition path and TabBeacon also has another production provider
(Agy). It must never be used to imply support for deferred providers.

Implementation rules:

```text
POSITIONING_PRIMARY=CODEX_AND_MORE
CODEX_ACQUISITION_PRIORITY=true
SUPPORTED_PROVIDER_TRUTH_REQUIRED_ADJACENT=true
CODEX_SUPPORT=production_capability_based
AGY_SUPPORT=production_exact_1.1.19
CLAUDE_SUPPORT=deferred
OPENCODE_SUPPORT=deferred
UNBOUNDED_PROVIDER_CLAIM=false
```

Candidate discovery copy, subject to final implementation-time length and
rendering checks:

```text
GITHUB_DESCRIPTION=Live status for Codex and more in Windows Terminal — no launcher required.
README_HERO=Live identity and status for Codex—and more—across Windows Terminal tabs, without changing how you launch them.
```

The README/support table must continue to state the exact production support
matrix. `and more` is a positioning phrase, not a compatibility wildcard.

## PR topology

Preferred structure:

```text
Planning PR  — v0.7.3 re-admission and execution docs
Train A PR   — G99 + G100 discovery/media work (PR #100 if safely reconciled,
               otherwise a clean successor)
Train B PR   — G101 README/crates.io/package polish
Release PR   — G102 v0.7.3 release transaction
Closeout PR  — metadata-only current-truth update after public verification
```

G99 and G100 are intentionally grouped because they share the public visual
surface and existing PR #100 evidence. G101 stays separate because package and
README risk is different from exact-window media capture.

During the pause, prioritize observation of Codex upgrades, multi-subagent

admission rather than growing out of this maintenance train.
