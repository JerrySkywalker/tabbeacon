# v0.7.3 positioning notes

The v0.7.3 public acquisition message is intentionally Codex-led while product
truth remains provider-specific.

Preferred shorthand:

> **Codex and more**

This is acceptable because Codex is the primary acquisition path and TabBeacon
also has an admitted production Agy integration. It is not a claim of generic
provider support.

Durable public surfaces must keep this truth visible:

```text
Codex CLI — Production, capability-based compatibility
Agy CLI — Production, exact admitted 1.1.19 profile
Claude Code — Deferred
OpenCode — Deferred
```

Candidate copy:

```text
GitHub description:
Live status for Codex and more in Windows Terminal — no launcher required.

README hero:
Live identity and status for Codex—and more—across Windows Terminal tabs,
without changing how you launch them.
```

Implementation may refine wording for length/readability, but must preserve the
same acquisition strategy and compatibility boundary.
