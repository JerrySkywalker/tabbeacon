## A. Supported guarantees / 支持的保证

- In previewed Control Center Repair and Workspace Alias Set/Reset, the original
  Preview baseline survives Confirm and reaches the actual conditional writer.
  Observed byte or file-identity drift refuses that approved operation. No automatic
  retry adopts new data as the approved baseline; inspect a fresh Preview explicitly.
  Direct CLI write subcommands are explicit requests against their invocation-time
  baseline; a preceding independent CLI inspection is not a transferable approval token.
- Registered cooperating Repair/Restore writers use the canonical-settings lock;
  Workspace Set/Reset use the existing registry lock and conditional preference
  writer, whose lock also covers lower preference-store writers. Conditional
  contention has one success and one refusal for the tested same-baseline pair.
- Unsafe recovery fails closed. Unknown ownership files, receipts and backups are
  retained; this contract does not authorize automatic cleanup of unknown data.
- Explicit confirmation or an explicit CLI write request, ownership, path identity
  and the product action allowlist remain required. Preview, focus, Help, refresh,
  custom keymaps and shared modal opt-in never grant permission or Hook trust.

Localized notices appear in Human write commands and Control Center. JSON/plain
retain their machine schemas and do not receive localized stderr notices; the
same documented limits apply, and explicit write subcommand Help states them.

- Control Center 修复和工作区别名 Set/Reset 的原始 Preview 基准贯穿 Confirm
  与实际条件写入。观察到字节或文件身份漂移即拒绝该操作；不自动重试或把新
  内容作为已批准基准。需要重新检查并明确批准新的 Preview。CLI 写入子命令
  本身是针对调用时基准的显式请求；先前独立 CLI 检查不是可转移的批准令牌。
- 已登记的 Repair/Restore 使用规范 settings 路径锁；工作区别名 Set/Reset
  使用既有 registry 锁及 preference 条件写入锁，底层 preference 写者也使用
  同一锁。在已测试的同基准两写者竞争中，仅一次成功、另一次拒绝。
- 不安全恢复必须拒绝。归属未知的文件、receipt 和备份保留，不自动清除。
- 显式确认或显式 CLI 写入请求、所有权、路径身份和产品 action allowlist
  仍是必要条件；Preview、焦点、Help、刷新、自定义键位和共享 Modal opt-in
  都不授予写入权限或 Hook trust。

Human 写入命令和 Control Center 显示本地化提示。JSON/plain 保持机器格式，
不接收本地化 stderr 提示；同样遵循本合同，显式写入子命令 Help 说明这些限制。

## B. Explicitly unsupported / 明确不支持

FOREIGN_WRITER_ATOMICITY=UNSUPPORTED_BY_V090_CONTRACT.
CROSS_FILE_CRASH_CONSISTENCY=UNSUPPORTED_BY_V090_CONTRACT.

The final check-to-replace interval cannot provide strong CAS against arbitrary
noncooperating writers. External editors and Windows Terminal settings writers
are not globally serialized by the product's advisory locks. Independently
committed settings/receipt or registry/preferences files have no all-or-nothing
crash guarantee. Stop competing external edits during explicit writes; a failure
may need inspection and recovery. This advice does not create stronger atomicity.

最终检查到替换之间的窗口不提供对任意非合作写者的强 CAS。外部编辑器和
Windows Terminal settings 写入不受产品锁的全局序列化保护。settings/receipt
和 registry/preferences 独立提交，不承诺跨文件崩溃时全有或全无。执行显式
写入前应停止外部并发编辑；失败后可能需要检查和恢复。这不是强原子性保证。

## C. Limited recovery / 有限恢复

Recovery is bounded to states with proved ownership and an admitted baseline.
Ambiguous receipt/orphan or foreign states retain evidence and refuse unsafe
restore or cleanup. Unknown data is never silently overwritten to complete recovery.
Not every crash point recovers automatically. Only a newly inspected, explicitly
approved baseline can authorize a later operation; do not delete evidence to force it.

恢复仅限所有权和基准已证明的状态。模糊 receipt/orphan 或外来状态保留证据，
拒绝不安全恢复或清除，不静默覆盖未知数据，不承诺所有崩溃点自动恢复。
后续操作须重新检查并明确批准；不得为了继续操作而删除证据。

## D. Independent qualification / 独立资格

Runtime cancellation is cooperative for admitted collectors. Drop can join
without a bound; strict native/OS I/O stall exit remains unguaranteed. DEC private
modes without trusted DECRQM readback remain UNPROVEN. Successful software draw
submission is not optical input-to-screen latency. Physical keyboard, mouse and
visual Owner acceptance remain independent. Public registry resolution, official
installation, merge, publication and release each retain separate gates.
OWNER_APPROVED_V090_BOUNDED_POLICY is not OWNER_FROZEN_TUC_PUBLIC_API.
HookStat-labelled synthetic fixtures do not prove current HookStat migration.

Runtime 仅支持经准入 collector 的合作取消；Drop 的 Join 可能无界，严格
native/OS I/O stall 退出不保证。无可信 DECRQM 的 DEC 私有模式仍 UNPROVEN。
软件帧提交不是光学输入到屏幕延迟；真人键鼠、视觉 Owner 验收仍独立。
公共 registry、正式安装、merge、publish 和 release 保留独立门禁。
本方案不冻结 TUC 公共 API，也不证明真实 HookStat 已迁移。
