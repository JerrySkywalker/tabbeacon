## Required and optional evidence

The current required capability is an enabled local `hooks` feature. A
positive local report permits the conservative command-Hook V1 contract. A
schema bundle generated by the installed binary is an optional enhanced
evidence surface: its content-free fingerprint gives `Full`; unavailable
schema generation gives `Degraded`; it never makes the integration unusable.

A feature report that explicitly disables or omits `hooks` is
`Incompatible`. A failed or malformed local feature probe is `Unproven`.
`Unproven` blocks a new rewrite but preserves an existing exact,
manifest-owned, trusted integration so normal `codex` use remains fail-open.

The old hybrid MCP contract is never inferred from a release number. It is
retained only when the ownership manifest already proves that exact server and
declaration family. This preserves manual trust and avoids transport churn.

## Forward input behavior

- Known events with additive fields normalize normally.
- Unknown events, including `Interrupt`, are ignored fail-open.
- Unknown optional fields are ignored.
- Missing required ingress fields fail only that Hook invocation.
- Missing optional discovery evidence is `Degraded`, not fatal.
- Missing required capability is `Incompatible`.

No Hook payload, prompt, conversation content, token, or credential enters the
cache or capability report.
