# v0.2 Release Record

TabBeacon `0.2.0` was released from
`0b1d5136833a05bf94b7d32c414a21da2f5ac78e` under tag `v0.2.0`. The public
crates.io package, non-draft GitHub Release, Windows x64 ZIP, and SHA-256
sidecar were independently verified after publication. The checklist below is
retained as the historical preparation record; it is not new authorization.

## Proposed version plan

The public version is `0.2.0`. The package, installation examples, and
changelog were bound to the exact release commit
`0b1d5136833a05bf94b7d32c414a21da2f5ac78e`.

## Required release-candidate evidence

| Area | Required final candidate evidence |
| --- | --- |
| Policy and source | L0 repository policy checks, whitespace/content review, and exact candidate SHA |
| Rust/build | locked full Rust suite and package-content inspection |
| Functional | isolated setup/uninstall, upgrade/relocation, workspace identity, worker lifecycle, guided setup, and status/JSON diagnostics |
| Visual | one interactive Windows visual run proving animation frames, stable workspace alias, semantic colors, static result/attention state, and cleanup/reset |
| Provider | isolated real-Codex smoke at the exact head, with daily launch still literally `codex` |
| Package | `cargo package --locked`, then `cargo publish --dry-run --locked` only after the version plan is in place |
| Artifact | reproducible Windows x64 ZIP plan with checksum sidecar and release-note limitations |

The exact-head contract remains:

```text
EXPECTED_HEAD == CODE_HEAD == VISUAL_HEAD
```

## Scenario matrix to exercise at the release candidate

- multiple tabs and same-workspace parallel sessions;
- Git linked worktree, non-Git workspace, and a workspace-alias collision;
- stale previous-turn event, subagent lifecycle, and compact lifecycle;
- working animation, result-ready, `PermissionRequest`, `SessionEnd`, terminal
  close, worker crash, missing worker/binary, and Codex disappearance cleanup;
- settings changes, guided setup Apply/Cancel, status and JSON diagnostics,
  binary relocation/upgrade, and fail-open behavior.

Existing focused tests cover many of these invariants, but they do not replace
the final exact-head visual and real-provider evidence required for publication.
The isolated dangling-config-link regression fixture runs when the Windows
runner has symbolic-link capability. The current local runner reports Windows
error 1314 while creating that fixture, so that scenario remains a required
release-candidate check on a capable runner; it is not silently treated as
provider evidence.

## Alias registry note

`KNOWN_SYNTHETIC_ALIAS_RESIDUE=true`. The registry is append-only so it
preserves stable assignments and has no generic deletion/pruning operation.
The residue must not be mutated by release preparation. It can affect a future
visible alias only if a later collision reaches its retained alias; no broad
cleanup is warranted. If a targeted cleanup is ever needed, design an explicit
ownership-safe migration with an Owner-authorized backup and review.

## Release outcome

Owner-authorized publication completed only after all final evidence was
accepted. The release transaction published `tabbeacon 0.2.0` to crates.io,
pushed `v0.2.0` at the release SHA, created the public GitHub Release, and
uploaded the verified Windows x64 ZIP and SHA-256 sidecar.
