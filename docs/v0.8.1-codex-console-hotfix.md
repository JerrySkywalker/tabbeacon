# v0.8.1 Codex Windows console hotfix candidate

This is a compatibility candidate based on v0.8.0, not a public release or v0.9.

## Evidence and scope

The official OpenAI diff from `rust-v0.159.0` to `rust-v0.159.2` adds
`CREATE_NO_WINDOW` in the Hook command builder and in JobObject's suspended
spawn and fallback. Registry command construction also uses the new background
command helper. Shell arguments, piped stdio, environment filtering, deadline
and successful helper preservation remain material parts of the launcher model.
See [command runner](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/hooks/src/engine/command_runner.rs),
[JobObject](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/utils/pty/src/win/job.rs),
and [registry](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/hooks/src/registry.rs).

The release-tree differential reproduces failed presentation: an inherited
console has the origin member and VT enabled, while the hidden-console launch
has a different console without the origin or VT mode. On this host `CONOUT$`
can still open in the latter. Its availability alone is insufficient authority.
The release Hook reaches ingress and fails its terminal write. This reproduces
the presentation part of the Owner incident; the Owner's one-second timeout is
retained as a failure fact, with its precise causal phase still unproven.

## Recovery boundary

The Codex adapter walks at most eight kernel-reported ancestor links. It checks
process liveness, creation ordering (PID-reuse rejection), OS session, and exact
canonical path of the PATH-selected native Codex image. The supported npm layout
is resolved from the official installation path; no process table, process
memory, command-line text, credentials or external environment is read.

For recovery, inherited `WT_SESSION` and the normalized Hook session must be
nonempty. Official `Hooks::new` snapshots `std::env::vars_os()` from the native
provider; it does not insert the current `CODEX_THREAD_ID`, which can instead
belong to an outer agent. The unchanged generated declarations have no environment
override. This supplies WT-session inheritance evidence, not an independent read
of the ancestor's environment.
The held native process handle and post-attach console membership check constrain
the target. Missing or conflicting evidence suppresses decoration fail-open.

Only the Hook detaches from its hidden console and attaches to that proven native
ancestor. It reopens `CONOUT$`, requires already-enabled VT, and retains all three
provider stdio handles. The existing session worker inherits the recovered
console with its explicit NUL handle list. Guard cleanup detaches the Hook after
its sink drops. No Codex console mode, provider source or trust state is changed.
An already healthy inherited console keeps its existing behavior.

There is no timeout increase, declaration-format change, provider addition,
launcher, global daemon, app-server migration, stdout OSC, TUI scraping or
Windows Terminal process attachment. Existing Hook hashes may still change if
the executable path changes during isolated candidate installation; any resulting
native Hook review stays manual.

## Qualification fixture

`scripts/codex-native-console-fixture.py` uses an actual installed native Codex
as a bounded **stdio-only test ancestor**. Its offline exec-server child launches
the fixture host; this is test infrastructure, not the product Hook transport.
No model request, network listener, trust mutation or daily profile is involved.
The fixture executes actual setup-generated `commandWindows` through the same
shell/environment/three-pipe model, suspended JobObject assignment and one-second
deadline, changing only the no-window flag. Private test consoles are owned and
hidden; no other tab/window is opened.

This proves synthetic launcher compatibility, not `REAL_PROVIDER_DELIVERY_PROVEN`.
Final native TUI working/completion colors, tool continuity and exit/reset require
one Owner-attended Codex 0.159.2 packet. Publication also requires exact candidate
CI, independent review, package smoke and explicit Owner authorization.
