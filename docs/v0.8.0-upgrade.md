# Draft upgrade and rollback path from v0.7.3 to v0.8.0

This is a candidate procedure for isolated qualification. v0.8.0 is not
publicly released or approved for the Owner's production installation. The
published v0.7.3 binary and literal daily `codex`/`agy` commands remain in use.

## Before a future authorized upgrade

Run `tabbeacon upgrade-preflight` and preserve any unowned or ambiguous process.
Record the exact installed source and binary checksum. Take a private,
access-controlled backup of the current TabBeacon configuration, workspace
preferences, and owned provider integration files. Include unrelated Hook
content and Codex/Agy/Cursor trust state in the inventory without copying
authentication data into a release receipt. Inspect `tabbeacon config show`
and `tabbeacon doctor` read-only before making changes.

Install a qualified exact candidate in a separate path for testing. Explicitly
preview and Apply only the desired provider preferences. Setup and Hook
reconciliation require exact ownership and may require manual provider trust
review; installation does not grant trust. Continue launching each provider by
its original command. Visible changes to an already active tab occur on the
next owned event or old tab close, not merely when Apply saves a setting.

## Rollback boundary

First stop using the candidate in its owned session and complete an exact-owned
worker preflight. Remove only the candidate's proved managed integration
entries, refusing drift; preserve foreign Hooks and settings. Restore the
pre-upgrade configuration, workspace preferences, and integration bytes from
the private backup after checking that no foreign edit occurred since the
backup. Reinstall the verified v0.7.3 binary from its original trusted channel
and verify the old settings, alias, integrations, and manual trust state. Merely
replacing the executable is insufficient.

An isolated synthetic rehearsal proved read-only v0.7.3 inspection, candidate
Cursor install/uninstall with foreign Hook semantics retained, portable v2
export/import preview, and explicit byte-identical backup restoration. Cursor
uninstall can leave empty event arrays and reformat the JSON; exact byte
restoration is a separate controlled rollback step. This synthetic proof does
not authorize or prove an Owner production upgrade or rollback.
