## Interaction and evidence

`tabbeacon ui` uses Standard by default. `tabbeacon ui --keymap vim` selects Vim;
`--keymap-file <explicit-file>` validates a session-only TOML overlay with the
shared validator. No implicit search, watcher or user configuration write occurs.
An invalid/oversized file retains the accepted map and displays a safe error.
Help and footer derive their keys from the effective map.

Tab/Shift+Tab switch panes. Up/Down operate the focused pane; PgUp/PgDn/Home/End
stay within rendered content. Enter on Appearance/Interface selects the details
editor. Left/right change only staged values. Escape leaves an editor or overlay;
q/Ctrl+C request exit through the dirty-draft confirmation gate.
Mouse clicks only acquire visible focus; a wheel scrolls the hovered pane without
moving keyboard focus. Resize discards old hit geometry. Overlays capture input.

Diagnostics Standard 1/2/3 select Codex/Agy/Cursor; m queries execution mode.
Integrations 1/2/3 select the provider, r inherits its preference and v previews it.
Vim reserves digits for counts (`5j`, `gg`, `G`, Ctrl+d/u, hjkl); provider and
workspace candidate queries use Alt+digits. Insert receives literal input and
cannot trigger q/m/digit business navigation. Ctrl+3 remains distinct from 3;
physical delivery depends on the terminal's enhanced-key protocol.

F2 changes Smart/Raw density only, using the same immutable snapshot revision.
Overview, Integrations, Hooks and Diagnostics project normalized, command-redacted
facts through one UiDocument and shared Ratatui panes. The other five screens
retain their staged editing, alias, session, interface and preview behavior.
Static PASS, current delivery UNPROVEN, blocked upstream, stale currentness and
snapshot freshness remain separate. Raw contains permitted normalized evidence,
never raw Hook commands, provider output, credentials or private session payloads.
English/Chinese, NO_COLOR, Compact and TooSmall layouts remain supported.

## Read-only refresh and exit admission

The first UI frame has no provider collection dependency. F5 submits an intent;
one background worker collects read-only product facts. Single-flight scheduling
retains at most one pending request. Epoch invalidation after successful Apply or
Repair rejects late results; dirty drafts and CAS conflicts survive refresh.
Redraw follows accepted fact or UI state changes, rather than every input poll.

One Codex capability pass (version, feature state, optional schema) feeds Doctor,
Hook Inventory, Matrix, Registry and presentation admission. One Agy version
observation is reused; Cursor uses static local ownership inspection with no CLI.
CLI deadlines are 2 seconds for version/features/Agy and 3 seconds for Codex schema;
the product collection budget is 12 seconds. Git metadata fallback is local-only
and has a 2-second own-child deadline. Optional schema hashing checks cancellation,
limits depth to 32, entries to 4096 and bytes to 16 MiB; executable hashing streams
at most 512 MiB. Codex manifest/Hook/config observations are each limited to
256 KiB with cooperative chunk reads and shared parsed values for Doctor/Inventory.
Presentation, Interface and Workspace Preferences use 256 KiB observational
reads. Agy observed config/manifest/backup uses the same bound and a streaming
512 MiB executable hash. Registry observation allows at most 4096 entries,
256 KiB per generation and 16 MiB total per format scan. Passive session scans
retain their 512-entry/128 KiB bounds with actual bounded reads and per-entry
cancellation. Windows Terminal policy retains its 2 MiB limit with bounded reads
and limits observational ownership receipts to 256 KiB.
Oversized/missing/failed evidence remains unavailable, unknown or failed; writer
input and backup paths retain their original behavior.

The adapter terminates and actually waits for only its own Child. It retains at
most 64 KiB of stdout, discards stderr and checks capture-file growth every 5 ms
(disk growth can overshoot between checks). There are no detached reader threads,
global PID scans or abandoned JoinHandles. Healthy local filesystem I/O is the
supported environment: an OS/filesystem stall cannot be forcibly interrupted by
Rust cooperative control. Network/blocked-filesystem collector exit remains
unqualified and is not admitted as safe runtime operation.

Shutdown restores raw/alternate/cursor/mouse/paste state before a 3-second join
budget. A timeout is an error, never worker-exit proof; shared Drop retains and
joins the worker. Only the bounded cooperative product adapter is admitted.
Controlled child and worker tests qualify normal cancellation/reap/join, not
arbitrary third-party collectors or pathological OS I/O stalls.

## Owner acceptance

Source/fixture CI, synthetic TestBackend timings, owned terminal presentation and
real human input-to-screen measurements are separate gates. The latter remain
UNPROVEN until actually executed. Old uncached collector P95 (3.77 seconds) is
not an input-to-frame measurement. The Goal artifact pack contains exact heads,
risk differences, focused results and the manual acceptance steps.

Review the candidate and its evidence. Then run the explicit development binary
in an owned Windows Terminal window, verify Standard/Vim/Custom, click-to-focus,
hover-wheel, overlay isolation, resize and all nine screens in both languages.
Use isolated configuration for Apply/CAS safety exercises. Do not replace the
daily binary or mutate daily Hooks/trust during acceptance. Merge, tag, publish,
install and Hook trust require separate Owner decisions.
