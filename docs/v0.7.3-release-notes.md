# TabBeacon v0.7.3 discoverability and distribution polish

v0.7.3 is a public-surface maintenance release. It improves how people find,
understand, preview, and install TabBeacon without changing runtime or provider
behavior.

## Codex-led discovery with exact support truth

- The repository description, topics, social-preview assets, and README hero
  lead with **Codex and more**.
- The adjacent support table remains exact: Codex is production-supported from
  positively established local capabilities, and Agy is production-supported
  only for the admitted 1.1.19 profile.
- Claude Code and OpenCode remain deferred; the positioning phrase does not
  claim otherwise.

## Deterministic real-Windows-Terminal demo

The README now shows a privacy-safe 10-second demo rendered by TabBeacon's
production presentation path in one stock Windows Terminal window. The demo
uses only the synthetic aliases `API`, `WEB`, and `DOCS`; it contains no real
model session, desktop capture, Owner identity, private path, private
repository, or unrelated window.

The qualification lifecycle creates an immutable exact-ownership record before
capture and revalidates the unique anchor TabItem, ancestor window, HWND, and
creator process instance before exact close. Ambiguous windows remain untouched,
and broad Windows Terminal termination remains forbidden.

## Simpler installation and cleaner package

The normal user path is now:

```powershell
cargo install tabbeacon
tabbeacon setup
codex
```

English and Simplified Chinese landing pages retain parity, important media and
links render from the crates.io context, and the crate excludes promo media,
social-preview assets, build evidence, frames, palettes, and FFmpeg binaries.

## Unchanged product boundaries

Daily commands remain literal `codex` and `agy`. v0.7.3 adds no provider,
wrapper, fake executable, PATH shadow, PTY host, global daemon, Hook-trust
bypass, automatic Owner configuration mutation, or native tab-icon support.
